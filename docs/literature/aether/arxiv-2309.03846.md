# Scalable Forward Reachability Analysis of Multi-Agent Systems with Neural Network Controllers

- **Key:** arxiv-2309.03846
- **Authors / organisation:** Oliver Gates, Matthew Newton, Konstantinos Gatsis; Department of Engineering Science, University of Oxford
- **Date:** 2023-09-07
- **Link:** https://arxiv.org/abs/2309.03846
- **Kind:** paper
- **Read from:** full text
- **Relevance to us:** 2 (useful)

## What they wanted, and why
Reachability tools for closed loops with a neural controller are all written for one network driving one plant model, and they get expensive as the state dimension grows. The authors' target is the case where several such agents are coupled through a neighbour graph - each agent has its own network, and each network reads its own state plus the states of a few neighbours. They want the same kind of safety statement (an outer set that contains every state reachable over a horizon) at a cost that does not rise with the whole system at once. The larger goal is to make sound verification usable on networked systems (a platoon, a power grid) rather than on toy single-agent loops. The framing is that tightness and scalability trade against each other, and this paper tries to win scalability without giving up the bound's soundness.

## What they studied
M discrete-time agents with linear time-invariant dynamics, each coupled to a neighbour set, each controlled by a multi-layer ReLU perceptron that takes its own and its neighbours' states, summed over neighbours, then passed through a box saturation. Two instances: a nine-vehicle adaptive-cruise-control platoon (state = distance error, velocity, acceleration; 2 hidden layers of 15 ReLU units; 0.1 s sample period) and a four-area automatic-generation-control power network with heterogeneous areas and one exogenous load input (2 hidden layers of 10 units; 1 s sample period). The unit of analysis is the per-agent reachable set at each step, represented as a polytope - in the experiments as a box.

## How they did it
Three moves, in order. First, a reformulation: the neighbour-summed controller is folded into a single larger perceptron whose input is the concatenated self-plus-neighbour state, built by block-diagonalising the per-neighbour weight matrices and sandwiching them between two selector matrices (one that broadcasts the agent's own state block to every branch, one that sums the branch outputs). The effect is that the controller is again a plain MLP of the concatenated state, so single-agent machinery applies unchanged. Second, the saturation is absorbed as two extra ReLU layers appended to the network, so the control limits live inside the network rather than in the analysis. Third, they take an existing quadratic-constraint / semidefinite-programming reachability method (Reach-SDP), which represents the input box, the ReLU relations and the output half-spaces as quadratic forms in one shared basis vector, and apply it once per agent, with the neighbour states entering as part of that agent's input box. Each output axis gets its own semidefinite program minimising that axis' half-space offset subject to a single linear matrix inequality; doing this for both signs of every axis yields a box, iterated step by step. Finally they extend the linear matrix inequality to model uncertainty, where state and input matrices sit in the convex hull of a finite list, by requiring the constraint to hold for every combination in that list - legitimate because the reachable-set matrix is affine in those matrices, so the hull average is dominated by the finite extreme cases.

## What counts as an explanation here
Not a description of the network, and not a predictive model of it. The product is a certificate: an outer polytope per agent per step, together with the argument that it contains the true reachable set. It is meant to be sound but not tight, and it predicts only in the weak sense of encircling - it says where the system can and cannot go, never why the controller does what it does. The uncertainty extension adds a second certificate layer, covering a family of plant models rather than a single one.

## How they judged success
Against the obvious alternative - stack all agents' states into one vector and run the same semidefinite method on the whole system - with the same bounds claimed, on wall-clock time. Table I sweeps the number of agents from one to five and reports total solve time for both. Visual checks overlay sampled trajectories on the computed sets for the platoon (with and without 1% multiplicative model uncertainty) and for the power network. The solver is CVX with MOSEK, run in MATLAB. There is no independent reachability tool, no exact-set comparison, no tightness or volume metric, no sampled containment test case added, and no baseline beyond the monolithic version of their own method.

## What they found
Decomposing by agent buys a large and growing margin: at one agent the two methods cost almost the same (3.85 s vs 4.01 s), and the gap widens steeply with size - at five agents the decomposed method is around 20.8 s against roughly 41,000 s for the monolithic run in the same table. The authors state that the bounds obtained are the same, so the win is time only. In the power network the coupling is more tangled (some areas have two neighbours, and areas differ), and the method still produces sets that the overlaid trajectories fall inside. Adding plant uncertainty enlarges the sets, which the authors attribute to the exact sets themselves growing rather than to a loosening of the bound.

## Limits and open problems they name
They offer future work on porting the decomposition idea to other reachability engines (specifically LP-based ones), on synthesising the controllers with reachability in the training loop, and on other activations and set representations. The paper's own scope limits are structural: every agent must be linear, the decomposition is only as good as the graph's sparsity, each agent's local problem still contains its neighbours' full boxes so the bound pays for coupling in state dimension, and the uncertainty family is a box-scaled nominal model, which is a very particular kind of model error.

## What we take from it
Three things. (1) A method: the block-diagonal-plus-selector construction turns a coupling pattern into a single larger network, which is the cheapest way we have seen to make a compositional system analysable by tools that only understand one network - the same closure instinct that the same group's single-model work uses, applied to coupling rather than depth. (2) A cost framing: the price of a certificate can be paid per component when the dependency graph is sparse, and the measured curve here is not a constant-factor speedup but a change in how cost grows with system size - worth adopting as the way we state our own cost, since a linear-in-agents number beside an exponential-in-agents one is not a fair comparison unless the growth law is what is compared. (3) A warning about how the win was demonstrated: the "same bounds" claim carries the entire argument and is never quantified - no volumes, no gap, no second tool - so the paper sells a speed result and the soundness half of the comparison rests on an assertion. For our account that means the decomposition claim and the equivalence claim are separate and must be reported separately, with the costs of both printed.
