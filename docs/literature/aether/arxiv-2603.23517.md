# Beyond Accuracy: Introducing a Symbolic-Mechanistic Approach to Interpretable Evaluation

- **Key:** arxiv-2603.23517
- **Authors / organisation:** Reza Habibi, Darian Lee, Magy Seif El-Nasr; University of California, Santa Cruz
- **Date:** 2026-03-06
- **Link:** https://arxiv.org/abs/2603.23517
- **Kind:** paper (position paper with a case study)
- **Read from:** full text
- **Relevance to us:** 2 (useful)

## What they wanted, and why
Accuracy on a held-out split cannot tell a model that implements the intended algorithm from one that exploits a shortcut, and the authors argue the problem is now acute rather than marginal: contamination in pretraining corpora is widespread, contamination detectors disagree with each other badly enough that clearing data before testing is not a realistic option, and even clean datasets reward annotation artefacts. Their larger goal is an evaluation that answers a mechanistic question — did the model use the computation we meant it to use? — instead of a surface one. The instrument they propose is a set of task-level symbolic rules that any circuit solving the task must satisfy, checked per example with ordinary interpretability interventions, so that the output is a pass/fail tally rather than a score. They deliberately scope this to tasks with a well-defined intended algorithm (grounding, retrieval, parsing) and disclaim open-ended or creative generation, where several different algorithms can be equally correct.

## What they studied
Two fine-tunes of TinyStories-33M, identical architecture and optimisation, differing only in one training condition: the DISABLED_SCHEMA model never sees the database schema and the Schema model always does. The task is NL-to-SQL on the TinySQL CS1 Synonyms dataset, restricted to `SELECT x FROM y` shapes, where the schema deliberately uses a synonym of the column name in the English prompt so that the answer cannot be read off the question alone. The unit of analysis is a residual-stream activation at the schema token position, swept across layers; the mechanism being tested for is a schema-checking circuit that reads the schema token and maps it to the output field name.

## How they did it
They first score both models the conventional way, on exact match and field-name accuracy, under both test-time conditions (schema present and withheld). Then they build 100 matched prompt pairs, each a clean prompt and a corrupted one differing only in one schema word, spread over five corruption types: in-schema synonym, out-of-schema synonym, in-schema unrelated word, out-of-schema unrelated word, and a mixed column/non-column swap. For each pair they compute a schema-sensitivity gap as the difference in logit-difference between the correct and incorrect answer tokens, clean minus corrupted. They then patch activations: cache the clean residual stream at the schema position, re-run the corrupted prompt at every layer with that cached activation substituted, and record the largest signed shift toward the clean preference as a fraction of the gap, capped at one, along with the set of layers reaching at least 90% recovery. Three rules are then thresholded over the per-example numbers — causal sensitivity above a gap threshold, fractional recovery above α, and agreement between the example's recovered layer and the modal recovered layer over the whole set — stacked so that rule three can only pass if one and two do. The reported quantity is the per-example pass rate for each model, with an alternative threshold set run as a sensitivity check.

## What counts as an explanation here
A three-condition pass/fail predicate about a mechanism, not a description of one. The rules are symbolically stated as properties any circuit that genuinely solves the task must have, and the framework outputs a percentage of examples on which all three hold; it is explicitly partial, aimed at deciding whether a particular named capability is implemented, and it does not attempt to describe the circuit's internal structure. The claim it is meant to support is a comparison between two trainings, and the intended use is a diagnostic decomposition: a sensitivity failure says the model ignores the input feature, a recovery failure says the computation is not localised, a consistency failure says processing is per-example rather than reused.

## How they judged success
Field-name accuracy and exact match on the standard split served as the comparator, and the framework's own metric is the all-three-rules pass rate over 100 controlled pairs with 20 examples per corruption category. Thresholds were R1 gap above 0.4, recovery at least 90%, and R3 modal-layer membership, with alternatives at gap 0.25 and 0.30 against recovery 80% and 95%. The evidence offered is the between-model difference in pass rate, a 95% confidence interval on the mean sensitivity gap per model and on the training effect, the per-category breakdown, and the reported robustness of the 10–20 point pass-rate advantage across all threshold combinations.

## What they found
Standard evaluation is silent about the difference they care about: the no-schema model reaches 93.5% field-name accuracy with the schema withheld at test time, and the schema model reaches 99.1% with the schema present, while exact match separates them only by the test-time condition (72.1% versus 94.0% with schema at both points, and a collapse to 10.4% for the no-schema model when schema is added at test time). Mean sensitivity gap was 1.88 (95% CI 1.44–2.32) for the schema model against 0.65 (0.39–0.90) for the baseline, an effect of +1.23 logits (0.79–1.67) that the paper describes as a 190% increase. Under the rule framework the schema model passes 76% of examples against 59% for the baseline, with per-category passes ranging from 55% (in-schema synonyms) to 95% (out-of-schema unrelated words), and the effect is largest for scrambled corruptions and smallest for synonym substitutions, which they read as partial acceptance of semantically related replacements. Among passing schema-model examples, layers 0–2 accounted for 89% of recovered layers, against 34% modal-layer usage in the no-schema model.

## Limits and open problems they name
Three, stated plainly: the rule thresholds need principled calibration, ideally from control tasks with known ground-truth mechanisms; activation patching carries distribution-shift risk and can let recovery proceed through confounding pathways, so they call for triangulation with path patching, causal tracing or ablation; and symbolic rules are hard or impossible to write for tasks without clear algorithmic primitives, which confines the framework to targeted capability assessment rather than holistic evaluation. They also name the statistical constraint that motivated the work — small evaluation sets lack the power to separate competence from pattern matching.

## What we take from it
Two things, one a format and one a warning. The format: a predictive white-box model's claim can be emitted as a small stack of thresholded predicates over the same per-example intervention numbers, with the stacking order ("this can only pass if that passed") doing the work of a diagnostic tree — cheap, and it degrades informatively, because the failing predicate names the kind of failure. The warning is the one the paper undercuts itself: their pass-rate gap and their confidence intervals sit on 100 examples, and the two headline numbers they compare are quoted from different tables with different pairings (93.5% on field accuracy for one model versus 99.1% for the other, and a 10.4% exact-match cell that belongs to a test-time condition neither model was trained under), so the "invisible to accuracy" claim rests on the choice of accuracy cell rather than on a matched comparison — exactly the two-denominator defect this folder keeps recording. The transferable baseline also needs care: the no-schema model is a deliberately crippled model, not a strong competitor, so the 17-point pass-rate separation demonstrates that the rules detect a missing input feature, which is the easy end of the question.
