# Scoring Explanations Without Reading Them: Structural Shortcuts in Automated-Interpretability Evaluation Data

- **Key:** arxiv-2610.37676
- **Authors / organisation:** Xupeng Chen; Dimension Gate (correspondence address at NYU)
- **Date:** 2026-10-10
- **Link:** https://arxiv.org/abs/2610.37676
- **Kind:** paper
- **Read from:** full text (v1, Sections 1–9 plus Appendices A–I; figures not inspected)
- **Relevance to us:** 3 (central)

## What they wanted, and why
Automated interpretability — the standard way SAE features and neuron explanations get scored — asks a model to predict where a feature fires, or to judge whether marked tokens fit an explanation. That score is then treated as evidence about the explanation. The author asks a prior question: can the score be obtained *without* reading the explanation at all, purely from how the evaluation item was constructed (where the window was cropped, which tokens were marked, which sequences were listed first)? If so, a high score says nothing about explanatory quality, and every cross-dictionary or cross-explainer comparison built on such data measures the data's geometry. The larger goal is a scoring standard where a score is only evidence when it beats the best explanation-free rule on the same items.

## What they studied
The evaluation data of four public pipelines plus the author's own control: Neuronpedia's stored fuzzing runs (GPT-2 small layer-8 residual-stream SAE, 500 features drawn at random, 1,001 stored scorer runs from gemini-2.0-flash, llama-3.1-70b-instruct and one claude-3.5-sonnet), the Gemma-2-2B layer-20 Gemma Scope features with stored runs (12 features, 27 newer runs), locally built delphi items (default and centred modes), SAEBench's scoring windows, OpenAI's 2023 neuron release (400 sampled GPT-2 XL MLP neurons with GPT-4's explanations, activations and per-token simulations), and a commercial typed decision model, Jev, plus an open 8B simulator. The unit of analysis is the *item* (a token window with a mark set) and the *feature*; the object being attacked is the scoring protocol, not the network.

## How they did it
Three propositions do the work. The first decomposes a pooled Pearson correlation into a within-sequence part `r_w` and a weighted-between-sequence part multiplied by the correlation ratio η of the true activations, which bounds every predictor that is constant within a sequence at η — and shows the sequence-mean oracle, given only each sequence's true mean, attains it. The second gives the exact score of a "1 on the centre token" prior in closed form from the mean activation at centre versus elsewhere, the centre fraction and the pooled spread. The third bounds any rule that reads only a statistic of the item's construction by half of one plus the total variation between its law on positives and on negatives. Each of these is then instantiated on real stored data: marks are rebuilt from the scoring fork's code because stored runs keep verdicts but not marks, and the centre and count rules are scored against the stored scorers' recomputed balanced accuracy. For each cue the author then builds or derives a cue-free counterpart — random-offset natural windows on OpenWebText for the position cue, a matched-mark construction for the mark cues (derived, not built), and the within/between decomposition for the sequence cue — and runs a preregistered ranking test asking whether the cue *reorders* features, with a synthetic control calibrating the instrument.

## What counts as an explanation here
The explanation is the model's text description of a feature, and the understanding offered is a *negative* but exact one: closed forms for what a cue-reading rule can score, plus a pairing rule that converts any scorer's number into an interpretable one by putting the best explanation-free rule beside it. It is not a model of the network at all — it is a guarantee about which numbers about a network's units carry information. The predictive content is a bound (η, the total-variation ceiling) that can be computed before any scorer runs.

## How they judged success
Balanced accuracy against rebuilt marks for fuzzing, pooled Pearson r over all tokens for simulation (recomputed from stored verdicts), sign tests over runs/features/neurons with two-sided p-values, Spearman rank correlation with bootstrap intervals for the harm question, preregistered decision rules with outcomes appended (including adverse branches), shuffled-explanation controls, sequence-mean and per-feature-offset oracles as ceilings, split-half reliability ceilings for the ranking tests, Holm correction on the rubric ablation, and a synthetic-data calibration of the harm instrument.

## What they found
The cues are strong and the scores are beatable without an explanation. On Neuronpedia's stored runs 91.3% of activating examples peak on the centre token, and the "yes iff the centre is marked" rule reaches balanced accuracy 0.979 against 0.838 for the stored scorers — beating gemini-2.0-flash (0.864) on 312 of 371 contested runs and llama-3.1-70b (0.812) on 437 to 23; a rule reading only the *count* of marks needs no inferred seed and reaches 0.969. The centre prior reaches mean pooled correlation 0.732, and the closed form reproduces per-feature scores to 10⁻¹⁴. On the Gemma runs with 127-token windows the position cue vanishes (centre prior 0.003) but the mark-count cue is strong (0.981 against 0.794). Current delphi removes the crop cue but always marks the same slot in negatives, so "index 24 not marked" reaches 0.978. On OpenAI's release the sequence-order rule scores 0.227 and the sequence-mean oracle 0.288, both above GPT-4's published simulator at 0.160. The harm question comes back adverse: Jev's stored-snippet scores track crop geometry (ρ_geo 0.512) but track its natural-window scores more closely (ρ_nat 0.732), so the preregistered verdict is "geometry confound present, ranking harm not shown" — what moves is the *level*, from 0.478 to 0.331, lower for 44 of 49 features. On cue-free random-offset windows the best fixed-offset prior scores 0.015 while Jev with the real explanation reaches 0.331 against 0.013 shuffled, splitting into 0.285 within-sequence and 0.045 between; Llama-3.1-8B with the original read-out reaches 0.194 against 0.019. Two open typed decision models did not beat their shuffled controls, so Jev is an existence proof rather than a recommended scorer.

## Limits and open problems they name
Stored-run marks are rebuilt from inferred code, and only the negatives' positions depend on the inferred seed. Whether scorers actually *use* the mark-count cue is unsettled: the feature-level correlations go one way, item counts are too few for the other direction. One SAE carries stored runs at scale; the Gemma result rests on 27 runs of 12 features; delphi items are built locally without the BOS token delphi would prepend. The harm test has no positive control on real data, so "no ranking harm shown" is explicitly not "no ranking harm". The matched-mark construction is derived but never built or scored. No current closed LLM simulator was run against Jev, and Jev's architecture and training data are undisclosed, so contamination by OpenAI's public 2023 release cannot be excluded. The API is near-deterministic, reproducing only 6.5–9.8% of token-level values exactly on re-scoring.

## What we take from it
A **measure** and a **warning**, tightly coupled. The measure: any number we report about a unit must be paired with the best value obtainable from the shape of the evidence alone — the construction baseline — and where we cannot compute that baseline we have not shown our reading carries information. This is the same discipline run 690's oracle bounded for a certificate (a sample-free prior beside the proof) and run 694 asked for on the read/write side, arriving now as a hard inequality: rules that see only the construction are capped by a total-variation term, and a reading that does not exceed the cap is measuring the harness. The warning is sharper than the ones the head already holds: **a per-unit reading can be perfectly accurate about where a unit fires and still be an artefact of the window you cut**, so our activation-based readings must be recomputed on windows whose offset is drawn at random and stated, and the discrepancy between the two (here a level drop of 0.147, with no reordering) is itself the reportable quantity. Third, the reordering test is the right bar for a ranking: beating an absolute score is not evidence that the ranking agreed with the geometry-free ranking, and the paper's own preregistered test declines to claim it — we should adopt its shape, a correlation of our ranking with the confound against its correlation with the clean measure, with a bootstrap interval and a split-half ceiling. Fourth, mechanical: activations must be recomputed with the BOS token or the first real token's residual outlier absorbs most of the dictionary's mass (84% median) — a harness detail that, unstated, silently reshapes an entire per-unit census.
