# Approximating Reachable Sets for Neural Network based Models in Real-Time via Optimal Control

- **Key:** arxiv-2211.03732
- **Authors / organisation:** Omanshu Thapliyal, Inseok Hwang (Purdue University, School of Aeronautics and Astronautics)
- **Date:** 2022-11-07
- **Link:** https://arxiv.org/abs/2211.03732
- **Kind:** paper
- **Read from:** full text
- **Relevance to us:** 2 (useful)

## What they wanted, and why
The authors point at a gap that the rest of this folder has been filling from the other side: when a plant's dynamics are themselves a learned model, none of the reachability machinery in control theory applies, because HJ solutions, polytope propagation and validated ODE solvers all assume the dynamics are written down. Where the verification community responded by bounding the network's internals (MILP and LP relaxations over ReLU units), these authors object on cost: those problems are re-solved every time step, one per layer, and are not real-time. Their proposal is to treat the learned plant as a black box, excite it with inputs, fit a local linear model from the excitations, and then run classical optimal-control reachability on the linear model. The larger goal is a real-time reachable-set approximator for learned dynamics that a designer can call inside a loop, and the paper's contribution is the choice of *what to approximate*: not the enclosure, but the dynamics the enclosure is computed from.

## What they studied
A single illustrative system, but a real one: a fully nonlinear 12-degree-of-freedom quadrotor (position, velocity, three attitude angles, three angular rates) with four rotor commands related to thrust and moments through a mixing matrix, learned from simulation rather than identified experimentally. The learned model is a causal multistep MLP (12 inputs, one tanh hidden layer of 256, 12 outputs) trained on 100 trajectories with an Adams–Moulton multistep scheme at a 0.1 s discretisation, 2000 epochs, reaching MSE 1.26e-3 in about 80 s on a CPU. The uncertainty is modelled as independent additive uniform noise of +/-0.25 on each rotor command, which is what makes the initial set and the admissible control set into polytopes (24 hyperplanes for the state set, 8 for the input set). The unit of analysis is a **hyperplane**: the reachable set is represented by the points where its supporting hyperplanes touch it.

## How they did it
Three stages, and only the middle one is new. First, snapshots of the learned model's input-state behaviour — obtained by feeding the network commands and recording its one-step outputs, so no data collection on the real plant is needed — are stacked into a window of width 8 and a least-squares regression (a pseudo-inverse, computed by SVD) extracts a pair of matrices mapping the current state and command to the next state; recomputing the window at each step gives a linear time-varying model. Second, this linear model is used in an optimal-control formulation of the reachable set: each support normal is propagated by the costate equation (the transpose dynamics run backwards), the point of contact on the initial polytope is propagated by the system with the command that maximises the inner product against the current normal, and the resulting hyperplane is proved to support the reachable set by showing the derivative of that inner product is maximal for that command — a one-paragraph Pontryagin argument. Third, the inner approximation is read off as the convex hull of the propagated contact points and the outer approximation as the intersection of the supporting half-spaces, so the same computation yields both an under- and an over-estimate. The windows are recomputed every 0.1 s over a 50-step, 5-second horizon. A second experiment repeats the whole pipeline with rotors 2 and 3 failed, which changes only the admissible input set (the failed rotors contribute bounded noise instead of commands) — the learned model, the lifting and the solver are untouched.

## What counts as an explanation here
A time-indexed family of polytopes: an inner convex hull and an outer half-space intersection, per step, over the horizon, derived from a fitted linear surrogate. It is not a description of the network and it says nothing about the network's internals — the network enters only as a new kind of oracle, one whose *outputs* are differentiated numerically by fitting rather than whose weights are bounded. The predictive object is the LTV model (A_k, B_k): it claims that the next state is approximately affinely related to the current state and command, and every reachable-set claim is a consequence of that claim, not of a network property. Completeness is partial by construction and the paper says so — the polytope can be refined arbitrarily by adding hyperplanes, and the surrogate improves with data and window width, but no rate is given for either.

## How they judged success
There is no benchmark and no baseline run. The evidence is three kinds of visual overlay — true trajectories against the learned model against the DMD-reconstructed trajectories, the last of which is the surrogate's fidelity check; the inner-approximation hulls in three coordinate planes against a random true trajectory and the input envelope; and the same for the rotor-failure case — plus one cost table that compares asymptotic complexity against an LP method and a MILP method rather than against implementations. The single numeric fidelity statement is a per-step computational increment under 0.5 s, described as sufficient for real-time. There is no measured gap between the inner and outer approximations (the paper constructs both and never compares them), no slack ratio, no runtime sweep, and no accuracy-versus-data-size curve — that curve is explicitly deferred to future work, along with a space-complexity analysis.

## What they found
The pipeline runs: reachable sets are produced for the nominal and the rotor-failure quadrotor, at under 0.5 s per step, from 100 training trajectories and a snapshot width of 8. The cost table claims the surrogate route is independent of network depth (O(1) in layers against O(L) for both LP and MILP methods) and cubic in state dimension per solved hyperplane, against exponential worst case for the MILP route and a fractional power of L*n for the LP route; the LP route is also noted to produce hyperrectangular — i.e. loose — enclosures. The failure experiment is the most informative result in the paper and it is reported as a negative one: with two rotors dead, both the learned model and the surrogate depart visibly from the true attitude trajectories, and the authors state plainly that the surrogate stays close to the *learned model* rather than to the truth. So the pipeline faithfully propagates whatever the learned model says, including its errors, and the reachable set is an enclosure of the model's reachable set — which is what the problem statement asked for and not what a safety verdict would need.

## Limits and open problems they name
The authors name the accuracy chain and honestly condition reliability on both links: the network must approximate the plant, and the surrogate must approximate the network, and no rate is given for either — the DMD convergence claim is cited generally rather than measured. They name the space complexity of the framework, the data required for a prescribed accuracy, robustness to parameter variation, and a plug-and-play wrapper around existing toolboxes as future work. What the paper does not name, and what the reading forces: (1) a least-squares fit on excitations of the network is a **local** linearisation of exactly the kind the intro criticises local-LTI control for, so the black-box advantage is bought back as a locality assumption that is never characterised; (2) the two experiments are separated by a change in the input set alone, and the run in which the *model* is wrong is the one where the reachable set is least trustworthy — a controlled demonstration that the error budget has a component the method cannot see; (3) both inner and outer approximations are computed and only the inner is ever displayed or checked, so the paper's tightness statement is unmeasured in the one place where its own machinery would have measured it.

## What we take from it
A method, a warning, and a sharp structural comparison. The **method**: when the object we need is a *set* through a black box, an alternative to bounding the box's internals is to fit the map that generates the set and bound that — the fit can be amortised, the bound is classical, and inner and outer approximations fall out of the same support propagation. The **warning**: a surrogate fitted to a black box inherits the black box's error and cannot report it, so any account built this way must be labelled as an enclosure of the model, not of the world — this paper says so, and it is the sentence most papers in the family leave out. The **structural comparison**, which is the reason this entry matters to us: this is the folder's first genuine **black-box** member of the closed-loop thread, and it reveals that the field's "sound versus cheap" debate has quietly been about a third axis, **white-box access**. Everything from runs 626–641 assumes the analyser can read the candidate set — unit by unit, layer by layer, weight by weight — and the family's whole cost structure (per neuron, per sign pattern, per generator) is priced in that currency. Remove the access and the same question has a completely different cost profile, and a completely different failure mode. For our goal — a predictive white-box account of a black box — the useful reading is that this paper is what the ablation *without* the white box looks like: it can produce a prediction and a set, and it cannot say a single thing about why the network did what it did. That is the value the white box has to add, and it is measurable against exactly this kind of baseline.
