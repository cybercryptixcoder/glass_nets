# Position-aware Automatic Circuit Discovery

- **Key:** arxiv-2502.04577
- **Authors / organisation:** Tal Haklay, Hadas Orgad, David Bau, Aaron Mueller, Yonatan Belinkov; Technion – Israel Institute of Technology (Haklay, Orgad, Belinkov; Mueller also), Northeastern University (Bau, Mueller)
- **Date:** 2025-02-07
- **Link:** https://arxiv.org/abs/2502.04577
- **Kind:** paper
- **Read from:** full text (arXiv HTML v1; abstract, SS1–SS7, references, Appendices A–F; every number here is a printed table cell or an inline prose value — no figure is the source of any number)
- **Relevance to us:** 2 (useful: the folder's circuit instruments have all scored *components* inside a fixed position-agnostic graph; this paper shows the aggregation over token positions is itself a hidden choice that flips both the ranking and the precision/recall of the recovered graph, and it supplies a measured size–faithfulness trade-off rather than a single faithfulness number)

## What they wanted, and why
Circuit discovery describes a model's mechanism as a minimal subgraph of its computation graph, and the automatic methods in use (attribution patching and its variants) treat every node as equally relevant at every token position: if a head is in the circuit it is in the circuit for the whole sequence. The authors argue this is not a harmless simplification. Distinct positions do distinct work, and a circuit that cannot say *which* position carries an effect cannot capture cross-position interactions at all. Their goal is an automatic discovery method that scores edges position by position, plus a way to make that usable on real datasets whose examples differ in length and wording — and they test whether the extra specificity buys a better circuit per edge, not just a different one.

## What they studied
Unit of analysis: **edges of a per-position computation graph** — each attention head is instantiated once per token position, and the writers of an attention head are split into value, key and query edges, so edges connect heads at *different* positions as well as within one. Models: GPT-2 small and Llama-3-8B (BF16, TransformerLens). Tasks: Indirect Object Identification (the ABBA and BABA templates), Greater-Than (GPT-2 only, because Llama-3's tokenizer splits four-digit years in a way that breaks the task — model accuracy 0.0% on it, quoted in their Table 2), and a WinoBias coreference set built from 33 template pairs and 32 stereotyped professions, split so the correct answer sits first or second and into Anti/Pro-Female/Male variants; the main WinoBias run uses the Anti-Female-I slice, where Llama-3-8B answers correctly 34.5% and with the biased answer 64.8%. 500 examples for discovery and 500 disjoint for evaluation in every task.

## How they did it
They first quantify what position-agnostic aggregation does, by ranking IOI edges on GPT-2 small under two aggregation rules: summing absolute scores across positions and examples (no cancellation) versus summing scores across positions *first* and taking absolute values across examples (cancellation possible). At the top 1% of edges the two rankings' set difference is 17.1% (against a 3.9% control built from three data subsets), Spearman rank correlation 0.760 against a 0.985 control, and the same comparison restricted to the max-versus-sum aggregation gives 17.5% set difference and 0.772 — so the aggregation choice, not sampling noise, moves which edges are near the top. The method, PEAP, keeps the edge-attribution-patching linearisation but applies it to *cross-position* attention edges: the corrupted head output is recomputed by substituting a counterfactual value, key or query vector at one source position into the same softmax attention, then projected through the output matrix, and the score is the change in that head's output dotted with the gradient of the downstream logit-difference metric. Circuits are grown by a greedy connected-subgraph search (Hanna et al.'s algorithm adapted to allow parent and child nodes at different positions): start from the final-position logits node, repeatedly add the highest-absolute-score edge that attaches to a node already in the circuit, then prune nodes with no path back to an embedding. For variable-length inputs they introduce a **dataset schema** — an ordered list of semantic spans that covers every token and recurs across examples, so "war" and "Black Plague" can both be one *Subject* span — and map each example's token-level edge scores onto an abstract graph with one position per span; the abstract circuit is mapped back to a token-level circuit for faithfulness evaluation. Schemas are produced automatically by Claude 3.5 Sonnet from five examples, unified across three candidate schemas, accepted only if it applies validly to at least 80% of examples, and optionally conditioned on an input-gradient saliency mask that marks each example's unusually influential token positions. Llama-3-70B and GPT-4o failed their validity thresholds and were dropped. Faithfulness is reported as two curves over circuit size: **soft faithfulness** (the metric's value with only circuit edges kept, divided by the full model's) and **hard faithfulness** (whether the final-token prediction is unchanged), and circuits must reach 90% valid examples per run, with all compared methods scored on the same intersected evaluation set. The schema pipeline is run three times per method and the highest-validity run is reported, with all three printed in an appendix.

## What counts as an explanation here
A circuit: a sparse set of graph edges, each labelled with the token positions (or spans) it runs between, grown greedily to preserve connectivity to the output. It is explicitly partial — the paper's claim is about the *size-versus-faithfulness trade-off* of the recovered subgraph, not about a complete description of the mechanism, and the authors say component-level analysis of the WinoBias result lies outside the study. It is predictive in a narrow, testable sense: the circuit's edge set is scored by keeping only those edges and measuring how much of the model's behaviour survives.

## How they judged success
Soft and hard faithfulness as functions of average circuit size, on held-out examples (the standard faithfulness-over-size protocol the folder already records from Hanna et al.). Selection controls: the 17% set-difference and rank-correlation figures in the aggregation comparison are bracketed by a within-method sampling control over three data subsets, with all differences significant at p < .01. For the schema pipeline: two intrinsic metrics — *validity* (automatic: all spans present, correct order, each token in exactly one span) and *correctness* (a human applies the generated schema and agreement is scored per span, averaged) — plus the extrinsic faithfulness curves as the real test. Human-designed schemas are the reference arm. No interval is printed on any faithfulness curve; the curves are plotted, not tabulated, so the strength of any "as good as human" claim rests on the curves being visually close.

## What they found
Position-aware circuits reach comparable faithfulness with far smaller circuits: the paper's summary is that position-aware circuits are smaller and land the same faithfulness with far fewer edges, with both precision and recall improving (illustrated rather than tabulated — the numbers here are the aggregation statistics, not the faithfulness values, which live in figures). Schema-based discovery beats position-agnostic discovery on every task and model; the LLM+saliency-mask pipeline matches and sometimes beats human-designed schemas (notably on Llama-3-8B IOI, which the authors read as a sign that the GPT-2-derived human schema does not fit the larger model), and mask-informed schemas beat LLM-only ones consistently. And in WinoBias, a bias-predicting circuit passes through a *drop* in soft faithfulness where the circuit's own predictions become correct far more often than the base model's, then rises again into biased predictions as it grows — the authors' suggested reading is that the same components feed both answers, which they leave unanalysed. A candid cost: the Greater-Than result collapses to "every word is its own span", which the authors themselves call trivial, so that task carries no evidence about schema quality.

## Limits and open problems they name
Variable-length inputs are only handled under an ordered-span assumption: the same spans must recur in the same order across examples, so two orderings of the same roles cannot be pooled. There is no gold standard for schemas, so there is no principle for what makes a schema good, and the authors list "devising general principles for effective schema design" as the obvious next step. Human schemas being strong is itself ambiguous — the best schema may not be one a human would write. Schema generation is brittle: the reported run is the best of three by validity, and the appendix shows validity as low as 48.1% (GPT-2 IOI-ABBA, LLM-only) and 55.1% on one trial of IOI-BABA. Two models, three tasks, one downstream metric per task, and no interval on any faithfulness comparison.

## What we take from it
For us, three things. (1) **A method**: PEAP-style position-specific edge scoring, and the schema abstraction as a way to carry a position-indexed readout onto variable-length inputs — directly reusable for a white-box model of a network whose probe sites are per-token. (2) **A warning with a number attached**: 17.1% of the top 1% of edges change identity under a change of position-aggregation rule with the model and data held fixed against a 3.9% sampling control, and 17.5% against 3.6% under the max-versus-sum rule — so an edge ranking that does not name its aggregation rule is not a finding yet. (3) **A discipline**: the schema is a *declared* partition supplied to the discovery procedure, exactly the situation the folder already flags (an objective does what it is told); the paper's honest version is that it reports validity and correctness of the schema separately from the faithfulness it buys. And the WinoBias curve is the sharpest reminder in the paper that size–faithfulness is not monotone in the useful direction: a larger, more faithful circuit can be a more *biased* one.
