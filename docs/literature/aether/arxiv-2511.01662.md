# Selecting valid adjustment sets with uncertain causal graphs

- **Key:** arxiv-2511.01662
- **Authors / organisation:** Zhongyi Hu, Stéphanie L. van der Pas; Department of Mathematics, Vrije Universiteit (Amsterdam)
- **Date:** 2025-11-13 (v2; v1 2025-11-03)
- **Link:** https://arxiv.org/abs/2511.01662
- **Kind:** paper
- **Read from:** full text
- **Relevance to us:** 2 (useful)

## What they wanted, and why
Adjustment-set selection is normally stated for a *known* DAG, but the DAG a practitioner actually has was learned from data and is wrong in places, so the set that is valid in the learned graph need not be valid in the real one. The authors ask how to pick sets that survive the graph being wrong. Their concession is to keep the part of the graph that learning gets right most often — the skeleton, the set of adjacencies — and treat only the *orientations* as uncertain, since the empirical observation they cite is that structure learners err on direction far more than on the presence of an edge. The larger goal is an uncertainty-aware front end to effect estimation: a set chosen now should not silently encode a commitment to a single orientation that the data never established. The paper is a statistics paper, not an interpretability one, but it is the folder's first entry that treats *the object the account hands downstream* as itself uncertain rather than as an estimate with error bars.

## What they studied
No neural models and no learned surrogate: the unit of analysis is a **set of variables** (an adjustment set) inside a **class of DAGs** sharing a fixed skeleton and, optionally, the same Markov equivalence class. Data are linear Gaussian or discrete, finite in the experiments and infinite in the consistency results. Treatment and outcome are fixed and singleton; causal sufficiency is assumed throughout; the skeleton is either the true one or the one returned by GES. The experimental subject is therefore the *choice of adjustment set* — a downstream decision made from a graph — rather than the graph itself.

## How they did it
The procedure has two halves. First, sample DAGs: since the skeleton is fixed, a DAG is the same object as a topological ordering of the vertices, so they run a Metropolis–Hastings walk over orderings with acceptance by BIC difference (an ordering move that keeps the treatment before the outcome; the proposal changes only the chosen node's parents and children, so it is a local graph edit). Second, compute the posterior probability that any candidate set is a valid adjustment set by averaging the graphical validity indicator over the sampled graphs, using the linear-time graphical criterion of Van der Zander and coauthors instead of d-separation per path. The naive version is impossible because the power set of variables is exponential, so the theory of §3 is what makes it tractable: they prove that when only one node moves in the ordering, a set keeps its validity as long as three quantities are unchanged — the region reachable along the skeleton between treatment and outcome, the colliders on those paths, and the forbidden set (descendants of nodes on the causal path); a weaker version checks only the symmetric difference in the forbidden set and the change in collider descendants, and a separate proposition says partial results still hold when only one of the two is unchanged. A further proposition lets them avoid testing every set at all: any valid set can be pushed toward the graph's *optimal* (lowest-variance) set, and the newly formed set is at least as efficient, so only subsets of the optimal set — usually one variable short of it — need be tested, which is where the quadratic per-sample cost comes from. Sampled graphs are never accumulated as a vote over edges; they are accumulated as a frequency table over sets, tested versus found valid, and the output list is truncated at a fraction of the maximum frequency.

## What counts as an explanation here
Not an explanation of a model at all — an **uncertainty-annotated decision**: a ranked list of adjustment sets, each carrying the posterior probability (well, the empirical frequency ratio) that it is valid, produced from a distribution over graphs rather than from a single graph. It is deliberately partial: it does not say what the graph is, only which sets are *stable across the graphs consistent with what is known*. The predictive content is a hedge: sets high in the list are ones the analysis can safely condition on without knowing the directions.

## How they judged success
Two metrics against baselines, plus a sanity theory. **Precision** is the fraction of returned sets that are actually valid in the ground-truth DAG; **MSE** is the error of the estimated treatment effect, averaged over returned sets when there is more than one. Baselines are the optimal set computed on the GES output graph and the optimal set computed on random DAGs drawn from the true skeleton. Environment: 100 random DAGs at each even node count from 6 to 20, expected edge degree 3, coefficients uniform on [−1, 1], 100 data points each, treatment/outcome pairs restricted to ancestor–descendant, 100 sampling iterations, truncated at several threshold fractions. Two ablation axes are the *skeleton source* (true versus GES) and the *amenability* of the true graph's CPDAG (a graph-theoretic condition under which a valid set can exist at all); a third varies sample size and sampling time. Theory: a complexity proposition (quadratic per sampled graph) and two limit results — the walk recovers the true Markov equivalence class, and given an amenable CPDAG any set whose valid-ratio converges to one is genuinely valid.

## What they found
With the true skeleton and the looser thresholds the returned sets are valid most of the time: precision sits around 0.68–0.81 across sizes at the top threshold and falls steadily as the threshold loosens, down to roughly 0.37–0.46 when everything that ever appeared valid is kept; MSE moves the same direction, from about 1.3–1.9 × 10⁻² to roughly 2.5–3.3 × 10⁻². With the GES skeleton precision drops by a consistent margin (e.g. 0.73 → 0.60 at six nodes, 0.77 → 0.62 at twenty) and MSE rises, most visibly at larger sizes — the skeleton assumption is doing real work. Against the optimiser baselines the comparison is not close in the direction that matters: the optimal set from the GES graph has *lower* precision than the sampled lists in every cell (0.41–0.52), and the random-DAG baseline is sometimes worse still, so the disciplined baseline is beaten by construction rather than by tuning. Amenability behaves as the theory predicts: precision for amenable ground truths is generally higher and, in the sample-size and sampling-time sweeps, climbs toward one for amenable graphs while flattening for non-amenable ones. Their own surprise is stated plainly — **MSE is sometimes *better* for non-amenable graphs**, which they attribute to those graphs being denser, so the effect and the set variances are distributed unevenly. The real-data example is Sachs (11 proteins, 7,466 samples), treatment Mek and outcome Erk, where their list is topped by {PKA} — the accepted optimal set — while GES's graph yields {Akt, PKA}, and they check the GES output is a wrong CPDAG in which Akt parents Erk.

## Limits and open problems they name
The skeleton is assumed known and correct; every validity claim is conditional on that, and they show the degradation when it is estimated. The effect must be linear-Gaussian or discrete with the parametric assumptions of the sampler, because the move-based invalidity lemmas are proved for that setting — though they say the push-toward-optimal proposition survives more general graph classes. The limit results are called a sanity check rather than a tool: with infinite data any learner identifies a valid set, so the interesting regime is the finite one, where no guarantee is offered. Practical failures are acknowledged: large samples make the walk stick, and their fix is to subsample the data and rerun rather than to fix the sampler; the threshold vector is a user knob with no selection rule. Uncertainty about validity is not propagated into the effect estimate — they flag that as future work. And a wrong skeleton is the failure mode with no defence inside the framework.

## What we take from it
- **A method: represent residual uncertainty as a distribution over the account, and hand downstream a *stability score per conclusion* rather than a single conclusion.** Our accounts are the analogue of their DAG: when a battery leaves several accounts admissible, the decision our consumer actually makes (which direction to name, which sites matter) should be scored by the fraction of admissible accounts in which it holds, not by whether it holds in the point estimate.
- **A framing: separate the part of the structure you are willing to assert from the part you are not, and price the assertion.** They assert adjacencies and sample orientations. For us the analogous split is often "which units interact" (cheap to establish, robust) versus "in which direction / with what sign" — and run 538's matching ledger is the same move with a different residual object.
- **A measure: precision of the returned set against the truth, and the effect error averaged over the returned set** — two numbers that keep a hedging method honest, because a list of ten hedged sets can beat a point estimate on precision while losing on the downstream error.
- **A warning that lands squarely on us: a confident downstream choice made from one estimated object can be less reliable than a hedged list.** Their baseline is the *optimal* thing computed on the estimated graph, and it loses precision to the sampler's list in every cell. Our "take the best account and report what it says" policy is that baseline.
- **A shortcut: locality in the space of accounts is what makes uncertainty averaging affordable.** Because one ordering move changes only a node's neighbourhood, validity of most sets is inherited and the per-sample cost is quadratic; without a locality argument the same averaging is exponential. Any of our samplers over accounts should be built so that neighbouring accounts differ locally, and the local-invariance argument for conclusions should be stated, not assumed.
- **A negative result worth quoting: the metric that should improve did not always.** MSE favoured the non-amenable graphs. A conditional on our side that changes graph density, or the number of competing accounts, can invert the direction of an error curve while every other check passes — the temptation is to report the precision story alone.
