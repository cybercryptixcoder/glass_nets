# Reachable Set Estimation for Neural Network Control Systems: A Simulation-Guided Approach

- **Key:** arxiv-2004.12273
- **Authors / organisation:** Weiming Xiang (Augusta University, School of Computer and Cyber Sciences); Hoang-Dung Tran, Xiaodong Yang, Taylor T. Johnson (Vanderbilt University, EECS)
- **Date:** 2020-04-26
- **Link:** https://arxiv.org/abs/2004.12273
- **Kind:** paper
- **Read from:** full text
- **Relevance to us:** 2 (useful)

## What they wanted, and why
A neural controller is popular exactly where safety matters most, and the authors open with the standard worry: a small perturbation in the input can produce a wildly different output, so a closed-loop system whose feedback path runs through a trained network cannot be certified by testing. Their target is the safety of such a loop over a finite horizon: compute a set that provably contains every state the plant can reach from a bounded initial set, and conclude safety when that set misses the forbidden region. The interesting stance is where they invest. Their previous paper estimated the network's output range by solving four convex problems built on a maximal-sensitivity idea, and the authors judge that machinery too expensive; this paper keeps the same interval-arithmetic soundness and replaces the optimisation with a handful of forward passes — simulations of the network itself — used to decide where to spend the arithmetic. So the larger goal is a cheap sound procedure, and the contribution is a scheduling rule, not a tighter relaxation.

## What they studied
Continuous-time plant `x' = f(x,u)`, `y = h(x)`, under a sampled-data neural controller: the network is evaluated at instants `t_k` and its output is held over each interval, which is what turns the loop into something a reachable-set tool can propagate step by step. The network class is any multilayer perceptron with weights and biases per layer, and — this is the deliberate generality — activations only have to be built from standard functions and be monotone, which the authors note covers logistic, tanh and ReLU, so nothing in the method is ReLU-specific. The unit of analysis is the **interval** (a box in input or output space) and the decision variable is the **width of the box on which the network is evaluated**. Two examples: a two-joint robotic-arm forward-kinematics network (2 inputs, 2 outputs, with normal, buffering and forbidden joint zones) and a `2x20` tanh-network adaptive-cruise-control loop with a 6-state two-car model sampled every 0.2 s.

## How they did it
Layer-by-layer interval propagation first. Under a monotone activation the interval image of a pre-activation sum is just the activation at the two ends, and the weighted sum's bounds come from a per-term sign rule, so the whole network's interval extension is a composition of per-layer cheap formulas — their Theorem 3.1 — with no optimisation anywhere. They then give an analytic handle on how bad that composition is: the extension is inclusion-monotone and Lipschitz with constant `xi^L * prod ||W^(l)||` (Theorem 3.2), and the "excess width" — the interval width minus the true image's width — is bounded by that same constant times the input width (Theorem 3.3). That bound is the pivot of the paper: for a fixed network the only lever left is the input width, and shrinking input width means more subdivisions and more cost. Their answer, credited to the Moore–Skelboe idea, is to subdivide only where it pays. The network is fired `N` times (randomly or on a grid) to get sample outputs and their bounding box; the input set is bisected; each resulting piece's interval image is computed and, if it falls wholly inside the sample box, accepted and never touched again, while pieces that stick out are bisected further until their input width drops below a tolerance. The claim in the prose is that this spends fine subdivisions near the boundary of the sampled output region and coarse ones in the interior where the interval image is already contained. For the loop, the second algorithm alternates the pieces: project the current reachable set through the output map, append the reference-input set, run the simulation-guided network routine on that box, then hand the resulting control interval to a plant reachability tool over one sampling period, and repeat; soundness of the composite is inherited from the one-step pieces (Proposition IV.1) and safety follows from a non-empty intersection with the unsafe set (Lemma II.1, Proposition IV.2). The cruise-control run uses their interval method for the network and an off-the-shelf tool for the dynamics, with tolerance 0.1 and a hundred thousand simulations.

## What counts as an explanation here
A box, plus a collection of finer boxes whose union is a sound over-approximation of the reachable set over the horizon, and a yes/no verdict on safety from whether that union meets the unsafe set. It is a proof object rather than a description: nothing about the network is explained, and the network enters only as a callable whose interval extension is known. What is predictive is the certified enclosure and the excess-width bound, which predicts *how fast the enclosure must grow as you refine* — a rate, not a set. Notably the sample box is used as a pruning oracle but is not part of the guarantee; the certified object is still the interval extension of the sub-boxes kept at the end.

## How they judged success
Two comparisons are made, and they measure different things. (1) **Cost at matched output**: on the robotic arm they run their routine and the earlier uniform-partition method at the same tolerance 0.01, report the number of input intervals each produced and its wall-clock time, and check that both land on the same output range; the arm case is then called safe because the computed range sits inside the specification box. (2) **A verdict of safety with a visual check** on the cruise-control loop: reachable sets drawn against 100 randomly generated trajectories, plus the relative-distance pipe shown clear of the velocity-dependent safe-distance threshold. There is no soundness experiment (it is a proof), no measured excess width against a true image, and no error-versus-tolerance curve; tightening the tolerance tightens the enclosure is stated, not plotted.

## What they found
The arm is the whole quantitative story and it is one row: `397` input intervals and `0.1423` s for the guided method against `16384` intervals and `4.4254` s for uniform partitioning, at the same tolerance and with the same reported output range `[-12.0258, 1.1173] x [2.8432, 14.8902]`, which lies inside the arm's specification set. The paper states this in two ways, as about 2.42% of the intervals and about 3.22% of the time, and calls it a 3% cost. The cruise-control verdict is that the loop is safe over 5 s of emergency braking, with the ego car starting from initial intervals on position, velocity (30 to 30.2 in both cars) and zero acceleration, gap 1.4 s and default standoff 10; the reported evidence is that the reachable relative distance never meets the safe-distance envelope, and that 100 random trajectories stay inside the drawn boxes. Nothing in the tables distinguishes how much of the saving came from the sample box versus from adaptive bisection versus from the tolerance.

## Limits and open problems they name
The method's own closing paragraph proposes applying the simulation-guided idea to methods that specialise in a particular activation — ReLU networks in particular — to improve their scalability, which is an admission that the gain here is bounded by the generality it buys. The other named open directions are broader controller models, other plant reachability approaches, and wider network classes. They do not name, and the paper does not discuss, what the honest reading forces: the pruning rule is not proved to preserve correctness by itself (what preserves it is that the final union is still interval images of a partition of the input box at or below the tolerance), the excess-width bound is on the *whole* network's width rather than on the pruning, no per-example count or runtime of the number of simulations is reported beyond the two settings, and the loop's verdict on the cruise controller is checked visually against 100 trajectories rather than by any independent exhaustive search, so nothing tells us whether the drawn boxes were tight or merely correct.

## What we take from it
A method and a warning. The **method**: a sample set of a black box is a free, always-correct hint about *where that black box's image is not* — points inside the sample box cannot be far outside it — and using it to decide where to refine converts a uniform cost into a cost concentrated at the boundary. That is a genuinely different way to spend a fixed budget from anything else in the closed-loop thread, and it buys a 41x reduction in intervals without any new soundness argument. The **warning**: the saving is reported only as a ratio on one example with the tolerance held fixed, so the paper gives no way to know whether the ratio shrinks at tighter tolerances (where nearly every box is near the boundary) — a fidelity dial with no curve beside it, the same defect runs 632 and 639 flagged. For our account, the excess-width formula is the reusable artifact: `w(E) <= gamma * w(input)` with `gamma` the layer-wise product of weight norms is computable *from a model's weights alone*, which means we can print an a-priori tightness prediction for any network before running a single interval propagation, and compare that prediction against a measured enclosure width. That is the closest thing in this thread to a number a white-box model can produce about a black box's reachable set without doing the reachable-set computation.
