## What they wanted, and why
An SAE lets you read one layer, but the question our project actually cares about is what happens between layers: does a feature found at layer 14 still exist at layer 17, in what form, and can you steer through it? The authors' observation is that every existing cross-layer dictionary trains on the wrong target — transcoders and CLTs reconstruct dense states, crosscoders share codes across layers, end-to-end SAEs optimise vocabulary output — and none of them trains a sparse code at one layer to predict the sparse code at the next. That missing correspondence, they argue, is why chains of features cannot be followed through the network. Their goal is a dictionary whose adjacent-layer codes are explicitly predictive of each other, so that a single feature can be tracked across several layers and intervened on. The larger aim is a representation that is both readable per layer and causally connected across depth, i.e. a step toward the predictive white-box model.

## What they studied
Eight language models spanning three families and 124M to 2B parameters: GPT-2 Small/Medium/Large, Pythia-160M/410M/1B, Gemma-2-2B, Llama-3.2-1B; plus a single-seed feasibility run on Mistral-7B-v0.3. Data is OpenWebText, exactly 1B unique tokens shared across all methods. The unit of analysis is the **sparse feature** at each intermediate residual-stream position (dictionary size 16·d), and beyond it the **chain** of features linked by adjacent-layer correspondence matrices. Interventions are applied to the sparse code itself (steering vector added to activations, or top-active features zeroed), not to residual-stream directions.

## How they did it
Each layer gets a TopK "sparse feature transcoder" with its own encoder and decoder; the encoder's TopK selects by *signed* pre-activation value so that an active feature always writes along its own decoder direction rather than its negation. Training has two phases. Phase 1 gives every transcoder a loose sparsity budget (K=64) and a conventional objective — predict the next layer's *dense* hidden state with squared error, and at the last layer match the output distribution in KL. Phase 2 is the paper's contribution: with sparsity tightened to K=32, each transcoder is fine-tuned to predict the next layer's *sparse code* — decode at layer t, pass the predicted state through the frozen suffix, re-encode with the frozen layer-(t+1) encoder, TopK-select, and match the real TopK code in squared error. Crucially, Phase 2 runs **backward, output layer first**, each trained layer frozen before the next one inward, so later layers' output-relevant features supervise earlier ones. Baselines are reimplemented in one codebase: plain SAE, transcoder, e2e-SAE, CLT, crosscoders, TopK-SAE, and a "shared encoder" variant that hard-shares encoder weights across layers. All methods are matched on tokens, batch size, active-feature budget and optimiser search. Steering vectors are built contrastively in sparse space (mean code difference between positive and negative sets), applied at every layer during generation, and — the methodological core — each method's strength α is calibrated so that all methods are compared at the **same intervention-induced output KL** (0.01/0.05/0.10 nats per token, primary budget 0.05), with task gains measured from each method's own α=0 sparse pathway. Every result is averaged over five seeds, seed is the unit of replication, and a claim counts only if S2S beats *every* baseline after Holm correction across 56 comparisons.

## What counts as an explanation here
A **feature dictionary with an explicit inter-layer correspondence structure**: a k×k linearised coupling matrix `M⁽ᵗ⁾ = W_enc⁽ᵗ⁺¹⁾ W_dec⁽ᵗ⁾` whose columns can be followed from layer to layer, plus sparse steering vectors over that dictionary. The explanation is partial by construction and the authors are unusually clear about it: the correspondence matrix drops biases and the input-dependent TopK support, so it summarises *potential linear coupling*, not causal contribution; a full causal trace of how one semantic feature transforms at every layer is named as not provided. Prediction is limited to adjacent-layer codes and to the effect of a calibrated intervention, not to arbitrary behaviour.

## How they judged success
Three families, deliberately separated. (1) **Correspondence**, from the weight matrix alone: Top-5 ratio (mass in the five largest normalised column entries) and column-wise effective rank (entropy-based support size, explicitly *not* the spectral effective rank); in Appendix B also ridge-regression R² of next-layer pre-activations fit on 100K tokens with disjoint 10K dev/test, and linear-kernel CKA. The authors state that all of these partly overlap with the Phase 2 objective and so are treated as verification that the optimisation did what it was asked, **not** as interpretability evidence. (2) **Intervention efficiency** on held-out external tasks at matched output-KL: sentiment shift of free 50-token continuations scored by a fine-tuned DistilBERT on SST-2's official test split, and MC1 accuracy improvement on TruthfulQA with a category-stratified split. Feature identification, strength calibration and test partitions are disjoint, and test scores are used once. (3) **Output preservation and causal relevance**: output KL of replacing a state with its sparse reconstruction, and CI — the extra KL caused by zeroing the m largest-*signed* active features (averaged over m=1,2,4,8). Controls that carry real weight: a shared-encoder variant, a compute-matched branch that runs the identical Phase 2 schedule with the *dense* objective, a random-order and a forward-order training control, an "identity" control (no parameters) that bounds what residual-stream self-similarity alone buys, and a "direct" full-rank k×k map that can absorb the transformation. A semantic check uses one LLM to describe features from activating spans and a second, method-blinded LLM to judge whether a source feature and its strongest successor are the same concept.

## What they found
- Correspondence is decisively reshaped: Top-5 concentration rises from the best baseline's ~0.34-0.39 to 0.49-0.59 (e.g. GPT-2 Small 0.345 → 0.495) and effective rank falls from the low twenties to ~11-17, on all eight models, significant against every baseline. Pre-activation R² roughly doubles the best baseline (≈0.39 → 0.54 on GPT-2 Small; ≈0.437 → 0.619 on Llama-3.2-1B) and CKA rises by roughly 0.15-0.20.
- At the primary matched budget of 0.05 nats/token, S2S has the largest task gain in **15 of 16** model-task settings, all-baseline-significant in **12**; the exception is sentiment shift on Pythia-160M, where e2e-SAE is marginally ahead and S2S's truthfulness advantage is not significant. Typical margins are small: truthfulness improvement 0.347 against e2e-SAE's 0.312 on GPT-2 Small and 0.550 against 0.471 on Gemma-2-2B; sentiment 0.167 against 0.155 and 0.213 against 0.193.
- Output preservation is a narrow win: averaged over the eight models, output KL 0.048 against 0.052 for e2e-SAE and CI 0.216 against 0.185, with two cell-level exceptions (e2e-SAE has lower KL on Pythia-410M at 0.053 vs 0.056, and higher CI on Pythia-160M at 0.179 vs 0.168).
- The controls do most of the persuading. The compute-matched dense branch — same Phase 1 checkpoint, same schedule, only the target changed — reaches Top-5 0.314 and R² 0.374 against S2S's 0.545 and 0.600, at a cost of five thousandths in hidden-state FVU; so the gain comes from the *sparse target*, not the extra pass. The direct k×k map shows the opposite dissociation: weight-level Top-5 of 0.766, higher than S2S, but R² 0.309 — at the no-parameter identity control's 0.323 — and output KL 0.185 against identity's 0.208. The authors read this as the map absorbing the transformation: concentrated weight coupling with no activation alignment. The identity control's 0.323 is their estimate of how much of *any* correspondence score is residual-stream self-similarity.
- Training order matters as claimed: forward direction and random order both underperform full backward chaining on every model; Phase 2 without Phase 1 pretraining gives the weakest truthfulness on every model. Hard encoder sharing is the worst variant on correspondence and output preservation alike, which the authors call a counterexample to "shared indices = shared features".
- Feature chains are followed concretely. A positive-evaluation feature at GPT-2 Large layer 14 keeps a focused successor through layer 17 (top-1 masses 0.31, 0.29, 0.27); other chains show a speech feature **splitting** into content and attribution successors (0.22 and 0.18), two attribution features **merging** (0.19 and 0.21), and a local-syntax feature **losing** its successor (0.17 down to 0.07). Across 20 chains the mean top-1 mass over four hops is 0.28/0.26/0.25/0.24 for S2S against 0.17/0.16/0.15/0.15 for e2e-SAE.
- The LLM-judged semantic check gives 72% same-concept for S2S pairs, 48% for e2e-SAE, 2% for random pairs (Fisher exact p=0.024), on 50 sampled layer-17 features. Ablating top-active features moves the output more than ablating magnitude-matched features, and by a wider margin for S2S (ratio 1.52 vs 1.37) while perturbing a similar share of the state (0.143 vs 0.146).
- Cost: 3.2 h on one A100-80GB for GPT-2 Large against 2.1 h for an SAE and 8.4 h for e2e-SAE; the all-layer α=0 pathway costs +6.8% perplexity and −2.2 points LAMBADA, less than the dense control (+8.4%, −2.9) and a transcoder (+11.8%, −4.3).

## Limits and open problems they name
Correspondence metrics overlap the objective; causal ablation reduces but does not remove the circularity and stays an aggregate diagnostic. No blinded human study, no expert feature-label judgement, no complete causal trace of a semantic feature across all layers. Matched output KL equalises the magnitude of distribution change but not semantic specificity or residual-stream geometry across methods. Steering is tested only on sentiment and truthfulness in English; robustness to adversarial prompts, long-form generation and distribution shift is untested. Uniform TopK may underallocate capacity at late layers; adaptive, joint and joint-dense-objective variants all diverged in multiple runs, and dynamic-sparsity (BatchTopK, JumpReLU) objectives actually *hurt* S2S, so adapting them is left open. The Mistral-7B run is single-seed, feasibility only, with no baselines. Their own explanation for Pythia-160M — too little capacity for adjacent-code prediction — is flagged as untested.

## What we take from it
- **A method — the matched-output-shift intervention protocol.** This is the cleanest version of a control this folder has been circling for many entries: instead of comparing "steering with method A at α=0.4" to "method B at α=0.4", calibrate each method's α to a common measured induced KL and measure the task shift from each method's own α=0 reconstruction. It converts a comparison across methods into a comparison at one operating point, which is what any of our intervention claims needs. Appendix A gives the full recipe: log-α grid on development contexts, bracketing expansion, linear interpolation in log α, and a declared primary budget fixed before test scores are touched.
- **A warning about correspondence scores, with a number.** The identity control scores R²=0.323 with *zero learned parameters*. Any adjacent-layer similarity we report must beat that floor, and 0.54 vs 0.32 is a much smaller claim than "doubled" sounds once you know a third of it is the residual stream not changing. Their Table 9 is also the sharpest illustration in the folder that a weight-space metric can be optimised directly: the direct map gets the best Top-5 of any variant (0.766) and nothing else.
- **A framing for the cross-layer white-box goal.** "Predict the next layer's sparse code, supervised backwards from the output" is a concrete alternative to reconstruct-per-layer, and the compute-matched control makes it credible that the target choice — not the extra compute — is doing the work. It also supplies the vocabulary (split, merge, lose) for what a feature chain does between layers, which is exactly the kind of prediction our model would need to make.
- **A caution on the LLM-judged semantic check.** 72% vs 48% vs 2% is a real ordering with a real null, but a blinded LLM judge on 50 features is a prefilter, and the authors label it preliminary. Useful as a cheap screen; not a substitute for human labels.
- **A shortcut worth copying:** reporting the intervention task gain *and* the reconstruction-damage numbers for the same all-layer pathway, so a reader can see that the method's steering reference is itself less degraded (+6.8% perplexity against +8.4% and +11.8%). That is the honest way to present an intervention method whose pathway is lossy by construction.
