# Kernelized Parameter Sensitivity Atlases for Amortized Conditional Interpretability

- **Key:** arxiv-2610.12737
- **Authors / organisation:** Davide Wiest, Ahanaf Hasan Ariq, Abdul Monaf Chowdhury (Axym-Labs, per the linked code repository; affiliation not stated in the HTML we read)
- **Date:** 2026-10-08
- **Link:** https://arxiv.org/abs/2610.12737
- **Kind:** paper
- **Read from:** full text (v2 HTML: main body SS1-6, Appendix A protocol including Tables A1-A4, Appendix B proof section for the normalization and kernel-approximation results, Appendix B.8 scope statement, Appendices C and D; figures not inspected as images)
- **Relevance to us:** 3 (central)

## What they wanted, and why

Gradient attribution tells you which parameters matter *for this input*, but it costs a backward pass per query; a single global importance vector is cheap but throws the input dependence away. The authors pose the middle option as a statistical estimation problem: profile a finite set of source inputs once, store those profiles next to a compact representation of each source, and then answer a new query from a forward pass plus a kernel lookup. The larger goal is stated as "scalable conditional interpretability" - making input-conditioned weight-level explanation cheap enough to run at query rate rather than as an offline experiment. The framing matters more than the estimator: they treat the stored profile as a *population target* estimated from samples, which forces them to say explicitly what a finite atlas can and cannot recover about any single query.

## What they studied

Three frozen pretrained models across three modalities: AugReg ViT-B/16 (86.6M params) on ImageNet for vision, Chronos-Bolt-small (47.7M) on the ETTh1 and Weather series for forecasting, and ESM2-35M (33.5M) on reviewed Swiss-Prot sequences for protein modelling. The unit of analysis is the **native parameter group**: for ViT, a coupled triple of one first-MLP-projection row, its bias and the matching second-projection column, giving 3,072 groups in each of 12 blocks and 36,864 total; for Chronos, 2,048 final-decoder feed-forward groups; for ESM2, 1,920 layer-3 outgoing feed-forward columns. The scalar functional is a logit margin in vision and protein, and a forecast-minus-last-observation in forecasting. In the neuron-localisation application the unit becomes the **MLP feature** (same coupling, deactivated by zeroing its input), and the reference score becomes gradient-times-activation.

## How they did it

For every source input they take one backward pass and record the squared gradient energy of each parameter group, normalised across the partition so the profile is a point on the probability simplex - this discards total gradient scale and keeps only where sensitivity sits. Each source is also passed through a query map: in vision the 1,000-prototype (or 800-prototype) response map over DINOv2-S CLS features, in forecasting the exact RBF over the final encoder state, in protein the sequence-mean final hidden state. A query's profile is then the kernel-weighted average of the stored source profiles, in the Nadaraya-Watson form; since the denominator is common to all groups, ranking is unchanged and the implementation stores one D-dimensional coefficient row per group and evaluates a dot product. Groups are added in descending score until a parameter-mass budget is reached - 0.02%, 0.05% and 0.1%, which map to 8, 19 and 37 ViT MLP features. Controls are: a constant-sensitivity baseline that returns the mean source profile to every query, a KPSA-1NN variant that returns only the single nearest source's profile, a categorical query space (class identity / calendar coordinates / residue identity), and a matched-shuffle that keeps representations and profiles but breaks their pairing. Evaluation never uses a query backward pass for the prediction, but *does* compute query gradients to define the reference rankings and the causal anchors.

## What counts as an explanation here

A **conditional sensitivity profile plus a retrieved set**: for a given query, a sparse set of native parameter groups, each carrying an expected share of infinitesimal perturbation susceptibility. The prediction is explicitly first-order - the profile is a hypothesis about which groups a small perturbation would move the functional through. The authors are careful about what the set is not: they define a "sensitivity circuit" as a conditional set of groups with measured local causal utility "without asserting signed directed edges", so this is strictly weaker than a circuit in the attribution-graph sense. It is a partial explanation by construction, and the paper's own error decomposition says so.

## How they judged success

Every claim is graded by an **exact forward assay, not by fidelity to the score**. For the sensitivity circuits, they perturb the selected parameters along antithetic Rademacher directions with sigma at 3% of the group RMS, 16-32 directions per query, and take the squared central difference. The headline metric is **causal-gap recovery**: the method's mean effect, minus the constant baseline's, divided by the direct per-query gradient's minus the constant baseline's - so constant sensitivity is 0% and a per-query backward pass is 100%, by construction. A second column reports **gradient-energy captured** relative to the same-budget direct-gradient selection, which the authors note matters separately because a set can hold energy without converting it into finite-perturbation effect. Circuit structure is tested by Jaccard overlap between two queries' selected sets as a function of representation similarity, against the shuffled-pairing control, and by a constant selection matched on *both* budget and per-layer group counts. Neuron localisation swaps in exact zero-feature deactivation with an action-matched gradient-times-activation reference. Intervals are 5,000 paired bootstrap resamples of queries for the primary figures and paired 95% t-intervals for circuit causal comparisons; the authors state these measure estimation uncertainty at fixed models, data and seeds, not training variation. Efficiency is measured on one RTX 5090 with batch 32, five warm-ups, ten timed batches, and peak allocated memory and persistent atlas size reported separately.

## What they found

At the 0.1% budget on sensitivity circuits, semantic KPSA recovers 34.7% of the causal gap on vision (interval [23.7, 47.1]), 46.5% on ETTh1, 50.2% on Weather and 33.2% on protein; the same rows capture 71.8%, 72.9%, 74.6% and 42.8% of the same-budget direct-gradient energy. The gap between those two columns is the paper's most honest number: in vision nearly three-quarters of the gradient energy buys about a third of the finite-perturbation effect, so the selected groups are first-order right and causally diluted. The categorical query space does well only in vision (39.4% gap, 75.8% energy, i.e. beating the learned representation) and collapses elsewhere (2.2% on ETTh1 with an interval crossing zero, 5.6% on Weather, 5.4% on protein). The KPSA-1NN ablation *beats* the kernel average on ETTh1 (52.4% against 46.5%) and also on Weather (46.7% against 50.2% - here it loses), i.e. it wins one forecasting setting and loses the other, which the authors read as local averaging paying off only when the query space supplies several genuinely relevant neighbours. For circuit structure, selections span 6.0 ViT blocks and 5.8 Chronos blocks on average, Jaccard overlap rises from the lowest-similarity bin to the top 1% bin by 0.177 in vision and 0.471 in forecasting versus 0.089 and 0.210 when the pairing is shuffled, and the top-bin absolute overlaps are 0.389 and 0.614; the exact susceptibility gain over a layer-count-matched constant selection is 26.3% of the direct-gradient scale in vision and 15.8% in forecasting, mostly retained when selection is restricted to the final quarter of blocks and substantially lost when restricted to the first nine. For neuron localisation at 0.1%, semantic KPSA recovers 66.5% of the attribution gap on vision while categorical KPSA (76.5%) and KPSA-1NN (74.8%) both beat it, and on protein semantic KPSA is best at 68.3% against 56.6% for 1NN and 4.4% for categorical - so no kernel wins everywhere and the paper says so. The efficiency points (Table A4, 6,400-source atlas): activation attribution runs at 551 images/s using 4.24 GiB peak with no atlas, semantic KPSA at 2,041 images/s using 0.41 GiB with a 112.5 MiB atlas, and a coarse 32-feature partition reaches 59.3% gap recovery with a 3.5 MiB atlas. Break-even for profile-only construction cost lands near 15,000 batched queries.

## Limits and open problems they name

The theory is deliberately modest: Theorem 3 splits the profile error into an irreducible representation term, a local target-instability term and a finite-source term, and only the third shrinks with more sources - so no atlas size recovers sensitivity variation that the query representation discarded, and the paper's own Proposition 2 is the formal statement that a good-enough representation is a precondition rather than a knob. The i.i.d. source assumption does not hold for the forecasting setting, whose sources are deterministic overlapping windows of one series; the authors invoke only the deterministic ranking statements there and explicitly decline a time-series extension. The efficiency numbers compare against a reference implementation of activation attribution that requests only the activations it needs, and break-even excludes representation encoding and prototype fitting, so it is a lower bound. The atlas covers feed-forward groups only for Chronos and ESM2 (attention and embeddings are outside the eligible scope), which means the forecasting and protein results say nothing about where sensitivity sits elsewhere in those models. Neuron-localisation queries are filtered to inputs the intact model already answers correctly. No signed edges are claimed, and the smoothness bridge between the infinitesimal target and the finite perturbation assay is stated as a local approximation rather than an identification. Two cost figures also disagree across the document - the abstract reports 0.44 GB against 4.55 GB peak memory while the body and Table A4 report 0.41 GiB against 4.24 GiB - which does not change any conclusion but is a reminder to quote the table, not the abstract.

## What we take from it

Four things, in order of use to us. **First, a scoring schema we can copy wholesale:** anchor every conditional-attribution result between a *constant* score (0%) and a *per-query oracle* (100%), print the gap-recovery and the energy-captured columns side by side, and never publish the second without the first - this is the cleanest version of the two-axis discipline this folder keeps arriving at, and the energy-versus-effect split is a reusable diagnostic for our own predictions. **Second, an error decomposition worth stealing as a reporting template:** representation error, local-instability error, finite-sample error, with an explicit statement of which term more data can reduce. Our white-box model should publish the same three-way split for any conditional prediction it makes, because it tells a reader exactly which knob to turn when the prediction is wrong. **Third, a warning about query representations:** the categorical query space is competitive in vision and worthless in forecasting and protein, and the 1NN ablation flips sign between two settings, so a representation-and-kernel pair is a per-setting choice that must be reported rather than a method property - our model must not claim a single conditioning space works across model families. **Fourth, a concrete amortisation accounting:** the atlas is one D-dimensional row per parameter group, break-even is measured rather than asserted, and construction cost is excluded from the headline speedup - all three are how we should report the cost of our own explanations. What we should *not* take is the causal claim: 71.8% of the gradient energy converting into 34.7% of the causal effect is the paper admitting that first-order selection does not transfer, and any prediction-under-intervention claim we make has to be licensed by the perturbation assay rather than by the energy column.
