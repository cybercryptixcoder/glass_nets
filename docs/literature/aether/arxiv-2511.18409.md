# Findings of the BlackboxNLP 2025 Shared Task: Localizing Circuits and Causal Variables in Language Models

- **Key:** arxiv-2511.18409
- **Authors / organisation:** Dana Arad, Yonatan Belinkov, Hanjie Chen, Najoung Kim, Hosein Mohebbi, Aaron Mueller, Gabriele Sarti, Martin Tutek (eight authors; the abs page carries no affiliations — the byline reads as a joint organiser group across the participating institutions, and the acknowledgements name individual grants rather than one lab)
- **Date:** 2025-11 (v1 2025-11-23; BlackboxNLP 2025 workshop findings paper)
- **Link:** https://arxiv.org/abs/2511.18409
- **Kind:** benchmark / findings report
- **Read from:** full text
- **Relevance to us:** 3 (central)

## What they wanted, and why
The field produces circuit-discovery and feature-alignment methods faster than it can compare them, and the comparisons it does publish are usually re-implementations by the paper's own authors on their own task, on their own ablation choice, against baselines they chose. This paper runs a public competition on a fixed external benchmark — the Mechanistic Interpretability Benchmark (MIB) — so that independent teams submit their methods to the same tasks, the same models, the same counterfactual inputs and the same private test split. The larger goal is measurement infrastructure: a leaderboard that stays open and turns "our method finds better circuits" into a number anyone can recompute. It matters to us because a white-box model has to be scored against something shared, and this is the field's current attempt to define that something.

## What they studied
Two tracks. **Circuit localisation**: methods that output a ranked set of graph components (nodes = submodule or attention head, edges = information flow) for a behaviour. **Causal variable localisation**: methods that map an activation vector into a feature space and name a set of dimensions as one causal variable, then intervene on it. Four models — GPT-2 Small (117M), Qwen-2.5 0.5B, Gemma-2 2B, Llama-3.1 8B — and four tasks (IOI, multiple-choice QA, two-digit addition/subtraction, ARC Easy and ARC Challenge), with RAVEL added for the variable track. Only model/task pairs where the model reaches at least 75% accuracy are evaluated, following MIB's own rule. The unit of analysis is whatever the submitter names: a component set for track one, a set of featurised dimensions for track two.

## How they did it
Each task ships train, validation and two test splits; train and validation are public so a method can discover and tune, the public test is public so iteration is fast, and the private test is withheld and reachable only through a HuggingFace leaderboard that queues submissions. Counterfactual inputs are fixed per example and identical for every team, so interventions are comparable across submissions. In the circuit track a submission uploads either one importance score per node and edge, from which the harness takes the top-k for each of nine sizes (k spanning 0.1% to 50% of components), or nine separate binary circuit files. Circuit size is not a raw count: including a node counts as including all its outgoing edges, and a single neuron counted against a submodule counts as one over the model dimension of that submodule's edges, then the total is normalised by the number of possible edges. Evaluation is activation patching that pushes the model toward the counterfactual answer, and every reported number is on the private split under counterfactual ablation. In the variable track a submission uploads a trained featuriser, its inverse, the indices that constitute the variable, optionally code for dynamic token positions, and optionally custom featuriser code. Faithfulness there is the share of examples where a distributed interchange intervention on the featurised dimensions changes the output in the way the high-level causal model says it should, averaged over counterfactual datasets and layers, with the best single layer also reported.

## What counts as an explanation here
A ranked list of components (or a featuriser plus a feature subset), scored by how well it carries a counterfactual behaviour — not a text description, not a mechanism story, not a claim about what the algorithm is. The explanation is deliberately partial and deliberately comparable: any method that can emit scores or a feature set is admissible, and nothing asks the submitter to justify *why* a component is in the set. This is the strongest property of the design and the source of its main blind spot (see the variable-track caveat below).

## How they judged success
**Circuit track**, two area-under-curve metrics computed by Riemann sum over the nine circuit sizes:
- **CPR** — integrated circuit performance ratio, area under the faithfulness curve. Faithfulness at a given circuit is (the task metric with the circuit minus the task metric with an empty circuit) divided by (the full model's metric minus the empty-circuit metric), with the task metric being the logit difference favouring the answer correct on the original input over the answer correct on the counterfactual. Higher is better.
- **CMD** — circuit-model distance, the area between the faithfulness curve and the ceiling of 1. Lower is better, and 0 means the circuit prefers the correct answer exactly as strongly as the full model.
The split between them is a design statement worth keeping: CPR rewards circuits that make the task work, CMD rewards circuits that reproduce the *whole* behaviour including where it goes wrong.
**Variable track:** interchange intervention accuracy — the fraction of aligned interventions where the featurised variable and the true causal variable produce the same output tokens — mean over datasets and layers, with the best layer in parentheses. A Random row and a set of MIB baselines (EAP and its mean/counterfactual/oracle-answer variants, EAP-IG on inputs and on activations, NAP and NAP-IG, DAS, DBM, DBM plus PCA or SAE, the full activation vector, orthogonal and non-linear projections) are printed beside every submission.

## What they found
**The random row is the most important row in the circuit table.** Random component sets score CMD 0.44–0.75 across the eleven model/task columns — a random ranking is, by this metric, only modestly worse than several published attribution methods. EAP with counterfactual ablation reaches 0.01–0.18 on nine of eleven columns, and its integrated-gradients variants reach 0.00–0.08 on most; the methods that win on CMD do so by a wide margin over both (one submission's ILP-plus-regularisation method is 0.01–0.08 across its filled columns, best at 0.01–0.02 on the small models). On CPR the random row is 0.68–0.75 while EAP with counterfactual ablation is 0.01–0.18 — i.e. on this metric the random ranking *beats* EAP, badly, in most columns. EAP with mean ablation is the only EAP variant that stays near random on CPR (0.16–0.30), and the ensemble submission (mean-averaging the three EAP variants) is strongest on CPR.
**What worked, by the organisers' own summary:** ensembling attribution scores, and regularisation that discards edges whose score sign flips across bootstrap resamples of the training data — the sign tells you whether an edge helps or hurts, and an edge that does both on resamples is noise. They also report an integer-programming formulation of edge selection replacing greedy selection, and a path-level method that ablates or counterfactually replaces whole computational paths rather than edges. Their hypothesis for why sign-stability filtering helps is regularisation: unstable edges that would otherwise enter the circuit are suppressed, so the circuit behaves more like the whole model.
**But there is no winner, and the organisers say so:** the best method depends on which metric you read. The gap between the top methods and the baselines is real on both curves, yet the rank order changes between CPR and CMD, and a competing submission's path method is strong on IOI/GPT-2 and near the bottom elsewhere.
**Variable track:** only one team submitted, and both of its methods are extensions of DAS. The simpler one passes features through a tanh without a hidden layer and wins nearly everywhere it is offered — on RAVEL with Llama-3.1 it is 84 / 70 / 72 against DAS's 75 / 58 / 63 for continent / country / language, and on MCQA with Qwen-2.5 it is 89 / 81 against DAS's 86 / 78. The MLP variant barely differs from it and only edges ahead on one MCQA column. **The most consequential numbers are the baselines, not the submissions:** the full activation vector as a "feature" scores 44–61 on MCQA's answer variable and 45–53 on RAVEL's continent variable, so a large share of any alignment score is available to a featuriser that does not localise anything; PCA-projected and SAE-based DBM variants generally do *worse* than plain DBM; and DAS itself varies enormously by task — 95 / 94 / 86 on MCQA's answer ordering variable but 31–54 on the arithmetic carry variable, where every method sits at 29–53.
**The organisers name the variable track's flaw explicitly:** non-linear featurisers are expressive enough to find almost any feature, including ones the model does not have, and they cite the memorisation problem that plagued probing classifiers plus work showing non-linear featurisers can be that expressive. Their conclusion asks for more controls before claiming a variable is in the model rather than in the featuriser.

## Limits and open problems they name
Four teams, ten methods — a small field, and the organisers concede it. The circuit tables have many empty cells, which they say may reflect cluster access or deadline compute as much as method scope. They did **not** evaluate runtime or compute cost, and say a direct comparison of compute requirements would be needed for anyone choosing a method. Their own suggestion for follow-up is finer-grained distributions to see when each method succeeds. The variable track had a single submitting team and no submissions at all for ARC or IOI, so its leaderboard is one method family compared mainly against baselines. Task coverage excludes any model/task pair below the 75% accuracy floor, so nothing here speaks to circuits for behaviours the model performs badly. No limitations section beyond these admissions.

## What we take from it
- **A warning with teeth about the metrics we would use.** Both circuit metrics here are anchored by a random-ranking floor, and that floor is not decorative: random scores CMD 0.44–0.75 and CPR 0.68–0.75, while EAP under counterfactual ablation — a widely used published method — lands at CMD 0.01–0.18 (better) and CPR 0.01–0.18 (worse than random). The lesson is not "EAP is bad"; it is that a faithfulness-style area metric can be gamed by hitting the ceiling on a few large circuits and destroyed by a few components that push the wrong way, so *CPR and CMD disagree by construction and must be printed together* — exactly the kind of paired reading this folder has been assembling from ERASER's two deletions and the circuit complement tests.
- **A reusable measure: the ceiling gap.** CMD prices a circuit against the full model's own behaviour rather than against task accuracy, which makes it sensitive to a circuit that solves the task for the wrong reason. Any account of ours that is meant to predict the model rather than the label should be scored against the model's full output distribution and not against the correct answer.
- **A reusable robustness trick: sign-stability by bootstrap.** Bootstrapping attribution scores over resamples and discarding edges whose sign flips is cheap, needs no retraining, and is the submission that did best on the metric that rewards reproducing the whole behaviour. This is the practical version of requirements the folder keeps restating — our effect columns should carry a stability interval, and components whose effect changes sign under resampling should be reported as unstable rather than averaged into a ranking.
- **A control this folder has been demanding, actually run: the full-vector arm.** The variable track's `Full Vector` baseline is a featuriser that localises nothing, and it scores 44–61 where specialised featurisers score 63–84. That is the skyline-versus-floor sandwich in one table: it says how much of an alignment score is free, and it is the row that tells you whether the extra 20–30 points came from localisation or from interpolation.
- **The warning we most need: expressive featurisers can find variables the model does not have.** Non-linear featurisers win here and the organisers themselves flag that winning may mean memorisation rather than localisation. Since our own read-outs are fitted, this is our failure mode too, and the same fix the probing literature already settled on applies — a control task or control dataset that shares the input and output space but has nothing for the read-out to find.
- **A framing: the leaderboard as an instrument, not a result.** What this paper demonstrates is that an external, private-test, fixed-counterfactual harness changes what gets reported — every submission is scored on data it never saw, under an ablation it did not choose. That is the cheapest available discipline for our own reported numbers, and it costs nothing but a withheld split.
