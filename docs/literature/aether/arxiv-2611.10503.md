# Learning a Unified Cross-Model Semantic Dictionary via Gated Bottleneck Sparse Autoencoders

- **Key:** arxiv-2611.10503
- **Authors / organisation:** Jinchi Zhu, Tie Luo (University of Kentucky — Department of Computer Science; Department of Electrical and Computer Engineering)
- **Date:** 2026-11-07
- **Link:** https://arxiv.org/abs/2611.10503
- **Kind:** paper
- **Read from:** full text
- **Relevance to us:** 2 (useful)

## What they wanted, and why
Several foundation models trained on similar data end up encoding much the same structure, but each keeps it in its own coordinate system, so a dictionary learned from one model is not a dictionary for another. The authors' complaint about prior cross-model work is precise: alignment-based methods (USAE, SPARC) put model-specific dictionaries into a shared *index* space, so feature number 812 "means the same thing" in each model while the atoms themselves remain separate and each still carries that model's own biases. What they want is one dictionary of atoms that every participating model's activations can be decoded from, plus a per-model residual dictionary to absorb what is not shared, so a concept found once can be interpreted, reused and transferred. This is a step toward an interpretability layer that is not tied to a single checkpoint — the "same concept in two models" claim made structural rather than textual.

## What they studied
ImageNet-1K representations from frozen vision backbones: ViT, SigLIP and DINOv2 in the main configuration, with ConvNeXt added in two appendix configurations (ViT/ConvNeXt/DINOv2; and all four). Features are taken from each backbone's final layer, token-level after mean pooling for linear heads. The unit of analysis is a **dictionary atom per stream**: one shared atom (a single vector claimed to be readable in every backbone's space) and, beside it, private atoms that belong to one model only. The comparison class is the same atom pair across models, which is the object the paper is trying to make singular.

## How they did it
Each backbone's features go through a frozen, randomly initialised linear projector with orthogonal initialisation, which maps everything to a common width while preserving within-model pairwise geometry (Johnson–Lindenstrauss); the projection is fixed on purpose so that alignment cannot be bought by a learned projection. A *single shared* sparse encoder then maps any model's projected token into a latent code, sparsified by keeping the top 32 activations per token. A global learnable gate vector, one value per latent dimension broadcast over all tokens, softly partitions those dimensions into a shared branch and a private branch, with a regulariser pushing gate values toward the two extremes; the split is one number per dimension, not per token or per model. One shared decoder reconstructs a common representation space from the shared code, and one private decoder per model reconstructs that model's private space from the private code. There are two reconstruction losses (shared and total) so that the private branch cannot quietly absorb everything, plus a cross-model alignment loss on the shared codes: per token the shared activations are normalised, a continuous Jaccard similarity is computed between each model pair's shared supports, and a stop-gradient overlap weight multiplies the difference in magnitudes on the overlapping support, so models are pushed to fire the same shared atoms with the same strength. Training uses AdamW for 30 epochs at batch size 32 on pre-computed features (three views per image: original plus two augmented), roughly 33 H200-hours for the three-model configuration; reconstruction and CLIP-adaptation numbers are averages over three seeds. For the unseen-model test the shared decoder, encoder and gate are frozen and only a single learnable linear adapter (replacing the random projector) and a new private decoder are trained on CLIP features.

## What counts as an explanation here
A **feature dictionary with a claimed scope**: each shared atom is offered as a human-readable concept, with example images that activate it (the paper's own visualisation picks the top-ranked images per atom and, for local concepts, the hottest region), and with the additional claim that the *same* atom applies to every model in the ensemble. Private atoms are the residual explanation, described qualitatively per backbone (ViT's private atoms read as class-discriminative textures and shape fragments; SigLIP's as language-tied visual prototypes; DINOv2's as geometry and spatial layout). It is partial — atoms, not circuits, no composition claims — and it is "predictive" in the weak sense of transfer: the dictionary is credited with working on a backbone it never saw.

## How they judged success
Four groups of measurement. (1) *Reconstruction fidelity* as R² on the validation set, reported separately for shared-only, private-only, total, and the private branch applied to the residual; baselines are defined by mapping their metrics onto the closest counterpart (USAE/SPARC self-reconstruction against GB-SAE total, their pair-wise cross-reconstruction against GB-SAE shared-only) with a single-model SAE as an empirical upper bound. (2) *Faithfulness* by concept attribution: a one-layer linear probe is trained on projected ImageNet representations, frozen, applied to the GB-SAE reconstruction instead, latents ranked by their contribution to the true-class logit, then the top-k are kept (Sufficiency) or removed (Comprehensiveness); a random orthogonal dictionary is the control, and prediction agreement after keeping or removing ten shared concepts is reported as a bar chart. (3) *Zero-shot cross-model retrieval* inside the shared reconstructed space with cosine similarity, instance-level and category-level Recall@k, against three baselines — random retrieval, private-component retrieval, and retrieval in the projected feature space, which for a frozen linear random projector is a geometry-preserving stand-in for the raw features. (4) *Reuse and generalisation*: the unseen-backbone CLIP result, an ImageNet linear-probe accuracy table over features reconstructed by projected / USAE / SPARC / GB-SAE, and a trained cross-model retrieval head with instance and category recall and mAP.

## What they found
Reconstruction: GB-SAE's total R² is 0.60 on average (ViT 0.56, SigLIP 0.58, DINOv2 0.65), shared-only 0.53 projected / 0.55 raw, and private-only only 0.10 / 0.12 — the shared branch carries nearly all of the reconstruction, which the authors read as evidence that the shared dictionary is where the reusability lives. Against baselines the total figure sits near the alignment methods' self-reconstruction (USAE 0.61, SPARC 0.55, single-model SAE upper bound 0.71) while the shared-only fidelity is well above their cross-reconstruction (0.20 and 0.41), and that gap is the comparison the paper says matters. Adding ConvNeXt changes almost nothing (mean total 0.63 for the three-model mixed set, shared 0.58 / 0.59) and a fourth backbone costs a little (total 0.62, shared 0.54 / 0.55) while the private share rises (0.11 / 0.12 → 0.15 / 0.16) — with more models, less is common. Faithfulness follows the intended split: shared concepts come out close to total concepts and clearly ahead of private ones and the random-orthogonal control; keeping the ten highest-ranked shared concepts reproduces the full dictionary's predicted class in 62–88% of cases, while removing them drops agreement to 26–48%. Zero-shot cross-model retrieval in the shared space beats every baseline by up to two orders of magnitude, with private and projected features sitting essentially at the random lines; the absolute numbers are low by design, since the pool is 50,000 validation images over 1,000 classes. The unseen backbone works with light adaptation: training only the adapter and a CLIP private decoder converges in 4–5 epochs to total R² 0.72 and shared 0.65, against the paper's stated 50% improvement over predicting the mean. Downstream, a linear probe on shared-reconstructed features reaches 0.86 top-1 / 0.97 top-5 against 0.76 / 0.92 for projected features, 0.72 / 0.92 for USAE and 0.78 / 0.93 for SPARC; with a trained retrieval head the shared representation gives instance R@1 0.99, category R@1 0.57, category R@5 0.81 and category mAP 0.48, versus 0.96 / 0.48 / 0.75 / 0.39 for projected features. The ablation is a trade-off rather than a curve: a heavier shared-reconstruction weight keeps the shared branch accurate but weakens cross-model retrieval, a heavier total-reconstruction weight hurts reconstruction, and a strong gate regulariser snaps gates shut and destroys alignment — the authors name the gate strength as the hyperparameter with no principled selection rule.

## Limits and open problems they name
Consequence of the design that the authors state and I take as its main weakness: **the shared concept is shared by construction, not by measurement** — the alignment loss forces the shared codes of different models to overlap, so "the same atom means the same thing in ViT and DINOv2" is entailed by the objective, and the paper's own evidence that it is *true* is the reconstruction and retrieval behaviour, not an independent check that the shared atom reads identically in each model (no per-model human read of the same atom number is reported). Other limits they name: vision only, ImageNet-scale only, downstream evaluation confined to linear heads, a pairwise alignment loss that grows with the square of the ensemble size, and the soft gate whose threshold has to be tuned. Not named but visible: the private branch contributes very little to reconstruction (0.10–0.12) even though the paper argues its job is residuals, so "the shared dictionary holds the semantics" and "the private dictionary holds the biases" are hard to separate from "the private branch is small"; and the frozen random projector means every input is already lossy before the dictionary sees it, with no control that repeats the run with a learned projector to price that loss.

## What we take from it
- **Method (dictionary construction):** factorise the representation into a *shared* code and a *private residual* code with a per-dimension gate, and make the two branches compete through two reconstruction terms. This is the cheapest design in the folder for "which part of what this probe reads is shared across models and which part is this checkpoint", and it is the structure our cross-model feature-comparison work currently lacks — we compare dictionaries after the fact instead of learning one code with an explicit residual.
- **Framing (scope of a concept claim):** a shared atom carries a scope claim with it. When we say a feature or a probe direction means the same thing in two models, the honest report has three parts: what the training objective forced, what an independent measurement showed, and how much of the reconstruction the private branch took. Here the objective forced the sharing and the independent measurement is retrieval, which is a good instrument but is not the same question as "a human reads this atom the same way in both models".
- **Measure (transfer to an unseen model):** the CLIP test is a clean template — freeze everything, allow one linear adapter plus a new residual decoder, and report the epochs to convergence and the fidelity reached. It prices generalisation in *how little may be retrained*, which is a stricter and more informative claim than held-out accuracy inside the training ensemble.
- **Measure (alignment baselines):** the paper's mapping of an incompatible baseline onto an equivalent metric (self-reconstruction ↔ total, cross-reconstruction ↔ shared-only) is the right way to compare against methods that do not produce the same object, and it also makes the paper's claim legible: the total figure is not better than the baselines, the *shared* figure is.
- **Warning:** a random frozen projection is doing real work here (geometry preservation) and no experiment removes it. For our own read-outs, when a fixed random map sits between the model and the instrument, a run with the map learned is the control that says how much of the result the map decided.
