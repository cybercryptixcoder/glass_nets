# Neural Network Verification in Control

- **Key:** arxiv-2110.01388
- **Authors / organisation:** Michael Everett (MIT, Aerospace Controls Laboratory), a tutorial paper supported by Ford Motor Company; the material it teaches is drawn from joint work with Golnaz Habibi, Björn Lütjens and Jonathan P. How
- **Date:** 2021-09-30
- **Link:** https://arxiv.org/abs/2110.01388
- **Kind:** survey/agenda (tutorial)
- **Read from:** full text
- **Relevance to us:** 2 (useful)

## What they wanted, and why
The tutorial exists because the field has two literatures that grew up apart: one that bounds what a network can output given a bounded input set, and one that says whether a controller is safe. The author's framing question is how to certify safety, performance and robustness of a learned component, given that the uncertainties a real system faces — sensor noise, bad state estimates, unknown initial conditions, adversarial input — all enter at the network's input and have to be carried through to the output before anything can be claimed about the plant. The obstacle he names at the start of the closed-loop part is specific and is the reason the paper is worth reading: a network's output feeds back into its input on the next step, so whatever looseness the analysis has at one step is not merely carried forward, it is amplified by the loop. The goal is therefore a single framework in which bounding a network and bounding a loop that contains it are the same procedure at different scales.

## What they studied
Feedforward networks with ReLU, sigmoid or tanh activations, written as a weight matrix and bias per layer; then a discrete-time, linear time-varying plant with bounded process and measurement noise (support known and finite, not necessarily Gaussian) and an output-feedback network policy, optionally with control limits; then, in the last third, a deep Q-network over a discrete action set with a bounded perturbation on the observed state. The unit of analysis is deliberately uniform across all three: a **set of inputs** and the **set it maps to**. For the isolated-network part that set is an L_p ball around a nominal input; for the loop it is a reachable set described either as an L_p ball or as a polytope given by a facet matrix; for the reinforcement-learning part it is an L-infinity ball around the observed state. So the paper's real object of study is not a model or a dataset but the *shape vocabulary* in which uncertainty is carried from one component to the next.

## How they did it
Everything is built on one optimisation problem: minimise a scalar function of the output over the input set subject to the layer constraints. Reachability, yes/no verification of a label, and minimal adversarial perturbation are then presented as three choices of that scalar, which is what lets the rest of the paper reuse machinery across domains. Because the layer constraints are non-convex, the applied half of the literature either relaxes them or subdivides the input, and the tutorial organises this as **propagators** (interval bound propagation, linear relaxations such as CROWN's affine envelope with its recursively computed slope and intercept matrices, and QP/SDP relaxations) and **partitioners** (single bisection, uniform grid, gradient-guided, shadow-price-guided, and the simulation-guided family). The unifying move is architectural: an *analyzer* chooses an output shape and a stopping rule and then drives a partitioner, which in turn calls a propagator per cell. The simulation-guided partitioner is described mechanically — sample the network N times, take the interval hull of the samples, push the whole input set through the cheap propagator, then repeatedly pop a cell and either accept it (its image already lies in the sample hull, or a cell dimension is under a threshold) or bisect it and push both halves; the greedy variant, from the author's own earlier work, instead always refines the cell whose image sticks furthest outside the sample hull, and it redefines "furthest" to match the requested output shape (L-infinity ball or convex hull). For the loop, the same relaxations are composed with the dynamics: the affine control bounds are chosen by the sign of the product of the output-specification row with the input matrix, folded into a single matrix and offset for the next-state facet, and the resulting bound on each facet is a linear program over the current state set, which collapses to a closed-form weighted-norm expression when the state set is a ball. He then does to the loop exactly what was done to the network — wraps the closed-loop propagator in a partitioner that splits the initial state set into a grid of cells and takes the union of the per-cell reachable sets. In the last part the same envelopes are applied per action: take the guaranteed lower bound of the Q-value over the perturbation ball for each action and pick the action with the best worst case, which is a different decision rule from the flag-something-as-sensitive output that supervised-learning certification produces.

## What counts as an explanation here
Not an explanation in our sense at all — this is a tutorial, and the artifact it teaches is an **enclosure plus a verdict**. The certificate for an isolated network is a pair of affine envelopes valid on the input set; for a loop it is an outer approximation of the reachable set plus the two conditions that the final set lies in the goal and no intermediate set meets an obstacle; for reinforcement learning it is a lower bound per action and the resulting robust-optimal action. What is genuinely predictive, and the reason the entry is filed as useful rather than background, is that the enclosure is a *function of the input set's size*: the paper is explicit that relaxations get looser as the input set grows, and that the partitioner exists precisely to trade set count against that looseness. That is a statement about a rate of degradation, and it is the thing our own account would need to reproduce.

## How they judged success
Mixed, and the mixing is the interesting part. For the isolated-network tightening there is no table at all: the evidence is a six-panel figure of the greedy partitioner with CROWN on one small network, counting propagator calls per iteration (one, three, five, thirteen, twenty-three, twenty-nine), plus a three-panel figure of one two-input, two-output, fifty-unit ReLU network inside the unit square, each panel a different requested output shape, each run stopped at two seconds, with tightness judged by eye against a sampled under-approximation. For the loop there is a single six-row table on a double integrator with a five-by-five ReLU controller, with a runtime column and an error column, and the caption supplies the multipliers used in the discussion. The headline comparison is the partitioned linear-program method against a previously published semidefinite method: about five times tighter in the caption's arithmetic and roughly a hundred and fifty times faster, versus the unpartitioned version of the same linear program which is put at about four thousand times faster and about seven times looser. The reinforcement-learning results are quoted from earlier papers as directions with a single instance: a multi-agent collision-avoidance run where the tighter envelope lets the agent reach its goal in 7 seconds instead of 9 while still avoiding the other agent.

## What they found
That the two paradigms can be nested, and that the nesting is what converts a method too loose for the loop into one that is not. The compositional result the author leans on is that analysing the network and the dynamics separately — bound the control, then apply the extreme control at every state — is qualitatively worse than optimising the next-state facet jointly, because the corner of the control interval is never actually produced at most states; the double-integrator errors reflect this, with the two separate-analysis rows far above the four joint rows. Second, and most important for the thread, the reported error column is a *ratio* of areas: the smallest axis-aligned box around sampled states divided by the area of the provided reachable set, minus one. Third, the tail of the figure discussion states the honest thing plainly: every method's tightness degrades as the horizon advances. Fourth, on the reinforcement-learning side the three differences from supervised certification he names are structural rather than cosmetic — a sensitivity flag is useless when an action must be chosen anyway, there is no correct label so actions need comparing by their encoded value, and a wrong action changes the state and therefore the future, so the value function is doing the work a static classifier cannot.

## Limits and open problems they name
Partitioning scales with the number of input dimensions that carry uncertainty, and the worst case is a split of every dimension, so he says outright that it will not work for wide input uncertainty and that different techniques are probably needed there. For loops, reachable sets cover safety only; stability and performance are less studied, the exact same conservatism and cost problems persist, and the whole construction assumes a good dynamics model is available. For the reinforcement-learning part the open questions are continuous actions, how to set the robustness radius when the true noise magnitude is unknown, and how to account for state regions never explored during training in a guaranteed way. Two things the paper does not address even though the reader will want them: the closed-loop numbers are all from one double-integral example with a five-unit-wide controller, and the section's deeper experiments are explicitly deferred to a companion preprint rather than reproduced here.

## What we take from it
A **framing** and a **measure**. The framing is the analyzer/partitioner/propagator triple, which is the cleanest statement in this thread of where a fidelity dial actually lives: the propagator sets the tightness available per call, the partitioner decides how the call budget is distributed, and the analyzer owns the stopping rule that turns a budget into a claim. Our account of a black box needs the same three roles separated, because otherwise "the model is loose" and "we spent the budget in the wrong places" are indistinguishable diagnoses. The measure is the sampled-area ratio, and it comes with a defect worth naming: the denominator is a sample-based under-approximation, not the true image, so the number is a ratio against a quantity that is itself estimated and will drift up as the sample count rises — which means it is comparable across methods only if the sample set is shared, and the paper does carry it that way. The three-item list of how reinforcement learning differs from classification certification also transfers directly: if our account is used to decide rather than to describe, the decision rule has to name the worst case it is protecting against, not merely flag that uncertainty matters.
